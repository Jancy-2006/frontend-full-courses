1.1 What is Frontend web development?

  • Front-end web development is the process of creating the visual and interactive parts of a website that users see and interact with.

    • HTML — The Structure of the Page

  • What is HTML?
    •
      1.HTML stands for Hyper Text Markup Language
      2.HTML is the standard markup language for creating Web pages
      3.HTML describes the structure of a Web page
      4.HTML consists of a series of elements
      5.HTML elements tell the browser how to display the content
      6.HTML elements label pieces of content such as "this is a heading", "this is a paragraph", "this is a link", etc.
    What is an HTML Element?
  • An HTML element is defined by a start tag, some content, and an end tag

    • CSS — The Style of the Page

  • What is CSS?
    •

      • CSS stands for Cascading Style Sheets
      CSS describes how HTML elements are to be displayed on screen, paper, or in other media

      External stylesheets are stored in CSS files
  • Why Use CSS?
    •
  • CSS is used to define styles for your web pages, including the design, layout and variations in display for different devices and screen sizes.

    • JavaScript — The Behavior of the Page

  • What is javascript?
    •
  • JavaScript is a high-level, interpreted programming language primarily known for enabling interactive and dynamic content on websites. It is one of the three core technologies of the World Wide Web, working alongside HTML (which provides structure) and CSS (which provides styling).

    What is Git?
  • Definition:
  • Git is a local version control system that tracks changes in your code and helps you go back in time if things break.
  • Analogy
  • Git is like a time machine for your code — every save becomes a version you can revisit.

  • What is GitHub?

  • Definition
  • GitHub is an online platform to store and share your Git-tracked code.
  • Analogy
  • GitHub is like Google Drive for code — it stores your work and lets you collaborate with others.

  • 🛠 Step-by-Step: Push Local Repo to GitHub

    • 1.Initialize Git (if not already done)

      git init
  • git init — What does it do?
  • The command git init initializes a new Git repository in your current directory. It sets up all the necessary files and folders Git needs to start tracking your project.
  • 🔍 What happens when you run git init:
  • It creates a hidden folder called .git/ in your project directory.
  • The .git folder contains all the internal data Git uses:
      • Commit history
      Branch information
      Configuration settings
      Staging/index files
  • Once this folder is created, your project becomes a Git repository, and you can start using Git commands like git add, git commit, etc.
  • In short:
  • git init tells Git, “Hey, start tracking this folder as a version-controlled project.”

    • 2. Add your files and commit

      git add .
      git commit -m "Initial commit"

    git add . — Stage changes

  • This command tells Git to track all the changes (new, modified, or deleted files) in your current directory and all subdirectories.
      • The dot (.) means “everything in the current folder.”
      It stages the files, preparing them to be saved in the next commit.
      But remember: these changes are not saved yet— they’re just staged.

    git commit -m "Initial commit" — Save a snapshot

  • This command creates a new commit
    • b> — a snapshot of your staged changes — and adds it to the project’s history.
      The -m flag lets you write a commit message inline.
      "Initial commit" is a common first message indicating the start of the project.
  • After this step, your changes are permanently saved in the Git history (locally).
  • In short:
      • git add . → Prepares all current changes for saving.
      git commit -m "message" → Saves those changes with a descriptive message.

    3. Create a GitHub Repository

      Go to https://github.com
      Click ➕ → New repository
      Name it my-first-git-project
      Leave it empty (don’t initialize with README)
      Click Create Repository

    4. Connect your local repo to GitHub

      Copy the URL of your GitHub repo. Then:
      git remote add origin https://github.com/your-username/my-first-git-project.git

    5. Push your commits to GitHub

      git push -u origin main
  • This command uploads your local commits to the remote repository on GitHub, specifically to the main branch. The -u flag sets origin/main as the default upstream, so future git push or git pull commands can be run without specifying the branch.

    • What is origin and main?

      origin = the nickname for your GitHub remote
      main = the branch you’re pushing
      In Git, origin is the default name given to the remote repository (usually on GitHub) that your local repo is connected to.
      main is the name of the primary branch you're working on and pushing your changes to.
  • You can add multiple remotes (like backup repos or forks), but origin is the default.

    • Introduction to Git & Github - III

    Why Branch in Git?

      You’re cooking your signature pasta dish. But this time, you want to try a spicy version with extra chili and garlic.
      Instead of tossing everything into the main pot and risking disaster, you scoop out a small portion into another pan — your experimental branch. You cook it separately, tweak the flavors, and taste test it.
      Love it? Great! You mix it back into the main dish — that’s a merge. If not? No worries — your original recipe is still safe.
      That’s branching in Git Create a separate version, experiment freely, and merge when you're ready.

    Experience It first

  • Before we branch out, let's refresh our memory:
      • Last time, you learned how to:
      Initialize a Git repository
      Track changes using git add and git commit
      Push code to GitHub
      Now let’s take it up a notch with branching.

    Step-by-Step: Create and use branches

    Method 1: Create the branch first, then switch to it

  • You can do this in two steps:
      • git branch add-dark-mode
      git checkout add-dark-mode
    • What’s happening?
        • git branch add-dark-mode : creates a new branch but doesn’t switch to it.
        git checkout add-dark-mode : switches you to that branch so you can start working.
        Useful when you want to create multiple branches ahead of time and switch between them later.
        Method 2: Create and switch in one go
    • Use the -b flag with git checkout:
        • git checkout -b add-dark-mode
    • What’s happening?
        • git checkout is the command used to switch branches.
        The -b flag means Create a new branch and switch to it in one go.
    • This is the faster, more common way to start working on a new feature or experiment.
    • Result Git now creates a parallel timeline of your project called add-dark-mode. You’re currently in that timeline, and anything you do from this point will happen in this new branch — not in main.

      Step 2: Make changes

    • This is where you code your new feature!
        • Open your code editor and make some changes — for example:
        Add a dark mode toggle button in your HTML.
        Write some CSS to change background and text colors.
    • Maybe add a little JavaScript to handle the switch.
    • These changes exist only in the add-dark-mode branch. Your main branch is untouched and still stable.

      • Step 3: Stage and commit your changes

        git add .
          git commit -m "Add dark mode toggle"
      • What does this do?
      • git add . tells Git: I want to track all the changes I just made in this folder.
      • This means “everything” in the current directory and its subdirectories.
      • "git commit -m " dark mode toggle creates a snapshot of those changes and adds a message describing what was done.
      • Think of a commit like saving a new version of your file in a video game — you can always come back to it later.

        • Step 4: Push your branch to GitHub

          git push origin add-dark-mode
      • What does this mean?
      • git push uploads your local branch to the remote GitHub repository.
      • origin refers to the default remote (your GitHub repo).
      • add-dark-mode is the name of the branch you’re pushing.
      • Now your work is live on GitHub, and others can see your new branch. It's ready for review or collaboration.
        • Basic Git Commands

        Activities and Commands

        git commit: Records the changes you've made to your files. Think of it as saving a checkpoint in the game.
        git branch <branch_name>: Creates a new branch. You’re telling Git, “Hey, I want to start a new version of my project called <branch_name>”.
        git checkout <branch_name>: Switches you to a different branch. It’s like saying, “Okay, I want to work on the <branch_name> version now.”
        git merge <branch_name>: Combines the changes from one branch into another. It’s like saying, “I'm happy with the changes in <branch_name>, let’s add them to the main project.”

        • to create column headers.

      • colspan="number": This makes a cell wider by letting it stretch across multiple columns. rowspan="number": This makes a cell taller by letting it stretch across multiple rows. Imagine a table as a grid of boxes. Using colspan is like combining boxes side by side. Using rowspan is like stacking boxes on top of each other and turning them into one tall box.

        • CSS Notes: Font & Text Properties, Inheritance, and Positioning

        A comprehensive guide for beginners and intermediate learners

        1. Font and Text Properties in CSS

        1. Font Family: Defines the typeface used in text. Common font families include serif, sans-serif, monospace, cursive, and fantasy. Example: font-family: 'Arial', sans-serif;.
        2. Font Size: Determines the size of text. It can be specified in pixels (px), ems, rems, or percentages. Example: font-size: 16px;.
        3. Font Weight: Controls how bold or light the text appears. Common values: 100–900, or keywords like normal, bold, bolder.
        4. Font Style: Used for italic or oblique text. Example: font-style: italic;.
        5. Font Variant: Creates small caps text using font-variant: small-caps;.
        6. Line Height: Specifies the vertical space between lines of text. It helps improve readability. Example: line-height: 1.6;.
        7. Letter Spacing: Adjusts space between letters. Example: letter-spacing: 2px;.
        8. Word Spacing: Adjusts space between words. Example: word-spacing: 4px;.
        9. Text Transform: Changes text case. Options: uppercase, lowercase, capitalize.
        10. Text Decoration: Adds effects like underline, overline, or line-through. Example: text-decoration: underline;.
        11. Text Align: Aligns text horizontally inside its container — left, center, right, or justify.
        12. Text Shadow: Adds shadow effects for stylish headings. Example: text-shadow: 2px 2px 5px gray;.
        13. Font Shorthand: Combines several font properties in one line. Example: font: italic bold 16px/1.5 'Roboto', sans-serif;.

        2. CSS Inheritance

        1. Definition: Inheritance in CSS means that some properties applied to a parent element are automatically passed down to its child elements.
        2. Inherited Properties: Typically, text-related properties (like color, font, and line-height) are inherited by default.
        3. Non-inherited Properties: Box model properties (like margin, padding, border) are not inherited automatically.
        4. Controlling Inheritance: The inherit keyword forces a child element to take the same value as its parent.
        5. Initial Keyword: The initial keyword resets a property to its default browser value.
        6. Unset Keyword: Acts as inherit for inherited properties and initial for non-inherited ones.
        7. Importance in Styling: Understanding inheritance prevents redundancy and helps maintain cleaner CSS code.
        8. Example: If you set body { color: blue; }, all text inside the body inherits that color unless overridden.
        9. Cascading & Specificity: Even inherited styles can be overridden by more specific selectors or inline styles.
        10. Best Practice: Use inheritance strategically to maintain design consistency and reduce repetitive code.

        3. CSS Positioning

        1. Definition: CSS positioning determines how elements are placed on a webpage relative to their parent or the viewport.
        2. Static Positioning: This is the default behavior; elements appear in the normal document flow without special positioning.
        3. Relative Positioning: Elements are positioned relative to their normal position using top, right, bottom, and left.
        4. Absolute Positioning: The element is removed from the normal flow and positioned relative to the nearest positioned ancestor.
        5. Fixed Positioning: Keeps elements fixed in place relative to the browser window, even when scrolling (e.g., sticky navigation bars).
        6. Sticky Positioning: A hybrid between relative and fixed; it acts relative until a scroll threshold is reached, then sticks to a position.
        7. Z-index: Determines stacking order of overlapping elements; higher values appear on top.
        8. Positioning Context: The nearest ancestor with a positioning property (other than static) becomes the reference for absolutely positioned children.
        9. Overlapping Elements: Use positioning carefully to prevent elements from hiding or overlapping undesirably.
        10. Practical Example: Tooltips, modals, and dropdown menus commonly use absolute or fixed positioning for precise placement.
